# 13.2 — A game's map, one tap away, and the app in Material 3 Expressive

**Status:** built on the morning of 2026-11-16, from the owner's interview of the same morning
(M1–M4) and their answer on the links (M5), right after 13.1's release. The map links live in the
private vault; nothing here names a game the owner plays.

Unless a path starts with `app/` or `documentation/`, it is relative to
`app/src/main/java/cloud/wafflecommons/pixelbrainreader/`.

## Where it starts (13.1.0)

- **A game's page** is a vault note with `game_template` (`data/games/GamePages`); the app opens it
  on route `game?page=<path>`.
- **In-app browsing** already exists for the share screen ("Open it here",
  `data/web/GuardedWebViewClient`: main-frame navigation and sub-requests to public addresses only).
  It uses the platform `WebView`; `androidx.webkit` is not a dependency (adding one is the owner's
  call, settled decision #9).
- **The privacy ledger** names every network caller (`data/privacy/`, `NetPurpose` keys persisted;
  a WebView is counted as a span with `PrivacyLedger.begin`/`end`).
- **The running session** is a Live Update with Stop (`GamePlatform.postRunning`); since 13.1 also
  "Still playing?".
- **Notification taps carry fixed screen keys**, never a vault path (`WidgetNav`).

## Decisions (owner, 2026-11-16)

1. **M1 Which maps.** Claude picks the best interactive map for each game, checked by hand; a game
   with no such map gets none.
2. **M2 No sign-in.** The maps are viewed signed out; what the owner finds goes in the game page's
   checklists.
3. **M3 Where a map opens.** From the game's page, from the running session's notification (the
   phone as a second screen while playing), and from the Games tab's cards.
4. **M4 Who finds the links.** Claude, for all the games, kept in each page's frontmatter (editable
   in Obsidian).
5. **M5 Where the links come from, first.** What Claude can open and check on its own: one
   family of game wikis. Two map sites refuse Claude's tools (fetching and searching, a site-level
   opt-out that is respected). The souls-like games first: "enough for a v1".

## The design

### P1. The links (M1, M4)

- A page's frontmatter: `game_maps:` (a list; the first is the main map), each entry an address
  or `Label | address`, so a page of map images says so ("Maps (images)") instead of passing for
  an interactive map. Pure `GameMaps`: public `https` addresses only (`ImportUrlValidator.isSafe`),
  named by the label, else by the address's last path segment, and by the site (from its domain).
  Unknown or broken entries stay in the note and out of the app.
- `GamePage.maps` (from `GamePages.parse`).

### P2. The map browser (M2)

- `ui/games/GameMapScreen` (route `game_map?page=&index=`): one `WebView`, full screen, the
  game's title and the site in the top bar, Back walks the page's history before leaving, Reload,
  Open in browser.
- View-only (M2): nothing offers to sign in. The share screen's settings (`configureForImport`:
  JavaScript on, as maps need it, no file or content access, no JavaScript bridge), third-party
  cookies off as WebView has them by default; a site's own cookies stay like a browser's, so a
  consent choice holds between visits.
- Guarded like the share screen's view: `GuardedWebViewClient` (public addresses only, every
  redirect); a page that won't load says so, with Open in browser.
- Counted in the ledger: a span for the screen's lifetime, `NetPurpose.MAPS` ("Game maps", key
  `maps`, persisted — never rename it).
- The screen stays on while a map is open (a second screen during play).

### P3. Where a map opens (M3)

- **The game's page:** a Map button under Start a session (several maps: a short menu), shown on
  a read-only device too.
- **The Games tab:** a map icon on each card whose page has a map.
- **The running session:** an "Open the map" action on its Live Update, when the game has a map.
  The tap carries the fixed screen key `game_map`, no path: the app opens the running session's
  game (nothing running: the Games tab).

### P4. The read-only device (settled decision #18)

Viewing writes nothing, so the maps work on a read-only device too.

## As built (13.2.0)

- `GameMaps` + `GameMap`, `GamePage.maps`; `NetPurpose.MAPS`; `WidgetNav.SCREEN_GAME_MAP`
  (`game_map`, no parameter); `GamesRoutes.MAP` (`game_map?page=&index=`, both optional),
  `GameMapViewModel` (no page: the running session's game) and `GameMapScreen`; the bars hide on

## The expressive pass (the owner's call, 2026-11-16)

After checking the maps on the emulator, the owner asked, before the release: "make every single
button, check item, radio button… Material 3 Expressive compliant", "13.2 must make the app fully
Material 3 Expressive compliant", "colourful but always respecting the device colour theming".

- **X1 Fully Material 3 Expressive.** material3 1.5.0-alpha23 draws the classic shape unless a call
  site asks for the expressive one, so every call site changed, by a scripted pass (Kotlin argument
  lists parsed, only files importing the material3 component, never the Glance widgets):
  - `Button`, `FilledTonalButton`, `OutlinedButton`, `TextButton`: `shapes = ButtonDefaults.shapes()`
    (the press morph); a button with its own shape keeps it, as `ButtonDefaults.shapes(shape = …)`.
  - `IconButton` and its filled, tonal and outlined forms: `shapes = IconButtonDefaults.shapes()`.
  - `Switch`: `thumbContent = switchThumb(checked)`, a check while on.
  - Segmented rows → connected button groups: `ConnectedButtonRow` + `ToggleButton` with
    `connectedShapes(index, count)` (Chat keeps its persona colours as `checkedContainerColor`).
  - `LinearProgressIndicator` → `LinearWavyProgressIndicator`; an indeterminate
    `CircularProgressIndicator` → `LoadingIndicator`, a determinate one → the circular wave.
  - Checkboxes, radio buttons, chips, sliders and the + menu (`FloatingActionButtonMenu`) were
    already the expressive components under `MaterialExpressiveTheme`.
- **X2 Colourful, the device's colours only.** `ExpressiveBadge` puts a card's icon on an
  expressive shape (`MaterialShapes` cookie, clover, sunny) in one of the scheme's accent tones
  (primary, secondary or tertiary container), both chosen by the card's title: `SectionCard`, the
  Settings rows, the Games cards. No fixed colour anywhere, so the wallpaper and dark theme lead.
- **X3 One header, everywhere.** "The app still feels the same on the tablet… push Material 3
  Expressive to an extreme", "make use of CortexTopAppBar to the fullest". `CortexTopAppBar` is
  every page's header, directly or through `FormScaffold`, and every page passes its `icon`: the
  emblem on an expressive shape in the page's tone, `headlineMediumEmphasized`, the subtitle a tonal
  pill, centred. The owner's review: the first version was small, its pill touching the emblem
  (now 80 dp, 104 dp with a pill, a 44 dp emblem); the large collapsing bar tried on the settings
  pages went back to the small centred one ("the top bar looked better on the Daily screen").
- **X4 Segmented lists and tonal cards.** The Android 16 list: rows in one group with extra-large
  outer corners, small inner ones and 2 dp gaps (`SegmentedGroup` for a column of rows,
  `segmentShape(i, n)` for a lazy list): Settings, the file list, the Games tab, Daily's Projects,
  Due today, Tasks and Tech watch. Cards tonal with `shapes.extraLarge`: `SectionCard`, habits,
  chores, projects.
- **X5 Daily.** Each block opens with `DailyBlockHeader` (its emblem, `titleLargeEmphasized`); the
  mood face sits on `ExpressiveHalo` (a slowly turning sunny shape); the mode and Toolkit chips are
  tonal buttons; the timeline's dots are cookies. The weather icon (an emoji) became
  `ExpressiveWeather`, the owner's pick among three ideas: the sky drawn from `MaterialShapes` (a
  turning sunny sun, puffy clouds drifting, pill raindrops, cookie snowflakes, a flashing bolt, fog
  bands), decorative (the condition is written beside it). It first sat on a halo; the owner's
  review ("too much inside the card") put it straight on the card.
- **X6 Games.** The Playing group is a `HorizontalMultiBrowseCarousel`; a game's page keeps its
  actions in a `HorizontalFloatingToolbar` with a vibrant FAB (start or stop), Started earlier, the
  map and Ask Claude (the map only on a read-only device).
- **Checked on the tablet** (the real vault, read-only, landscape): the game page, Games, Settings,
  Habits, Chores, Projects, Life Stats and Daily. One regression found and fixed there: the level
  card's XP wave read poorly in `primary` on its `primaryContainer`; it now uses the container's
  content colour and a 6 dp stroke.
