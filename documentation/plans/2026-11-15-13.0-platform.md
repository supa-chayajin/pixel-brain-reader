## Design

### X3 — The privacy ledger

- `data/privacy/PrivacyLedger`: what the app sends, recorded where it leaves.
  - What's recorded: a host, a purpose, bytes sent and received, and a count. Never a path, a
    query or a body.
  - Days are aggregated in memory, then written to `filesDir/privacy_ledger/<date>.json`.
    Days older than 30 are deleted.
- **The OkHttp clients** carry `LedgerInterceptor`: the shared client (weather, the GitHub
  sign-in) and the PSN client.
- **The calls outside OkHttp** record themselves, with bytes from the app's own traffic counters
  around them, marked approximate:
  - JGit (pull, push, fetch);
  - the Google API transport (Calendar, Tasks);
  - the page loader (imports, the tech watch).
- **The page:** Settings › Integrations › Privacy ledger.

### X5 — Wrapped

- `data/wrapped/Wrapped` (pure) turns the year's facts into cards:
  - notes created and edited (git history);
  - top folders;
  - mood (the average, the best month);
  - habits (check-ins, the longest streak);
  - sleep and steps (averages over measured days);
  - games (sessions);
  - XP.
- **Honest numbers:** a card without data is left out.
- **The screen:** `ui/wrapped/WrappedScreen`, full-screen cards in a pager, opened from a Life
  Stats top-bar action.

### X2 — Capture anything

- **Entry points:**
  - a photo picked in the capture screen (the Photo Picker, no permission);
  - an image shared to the app.
- **Reading:** ML Kit reads the text on the phone.
- **What it writes:**
  - the photo, compressed (1,600 px, JPEG) and kept in the vault beside a new inbox note;
  - the note itself: the embed, then the text under `## Texte`.

### D5 — Where a note lives

- The note header gets a second line under the title: the note's folder as a path
  ("20_Projects › 21_Waffle_Framework › Notes", "Vault root" at the top).
- A tap opens that folder in the file list, and goes back to the list on a phone.

## As built (2026-11-15)

- **D5:** the folder line is part of the title's tap target (both lines, about 44 dp tall), so the
  smaller line isn't a target of its own. The note stays selected when a phone steps back to the
  list, as the system back leaves it.
- **X3:**
  - One method for every call, so the sizes add up: the phone's own counter for the app, read as
    each call starts and ends, shared between the calls open at that moment. OkHttp's exact byte
    counts would have been counted a second time by the unnamed pool.
  - A global switch like `VaultWriteGate`, installed before anything talks to the network and a
    no-op in unit tests, rather than a dependency threaded through nine constructors.
  - The git commands run exactly as before inside `syncTraffic`: the transport itself isn't
    touched (gate 1: sync).
- **X5:**
  - The XP card shows the level and all the XP so far: a year's gain isn't kept anywhere (the
    weekly reviews keep a total from their first week only).
  - Focus has no card: a session isn't kept once it ends.
- **X2:**
  - The OCR text goes into the capture's field, so it can be corrected before Save; a shared image
    is saved at once, like an imported link. So the note has no `## Texte` heading: the embed, then
    one body, what was typed and what the photo said.
  - The photo is kept through the attachment writer the editor's drops use (the vault's Obsidian
    attachment folder), named like a pasted image.

## The pre-release review (2026-11-15, 21:45)

The owner asked, before the release, to "make sure everything is implemented correctly for v13".
The 13.0 commits were read against the plan, the settled decisions and CLAUDE.md. X3 and X5 had
nothing to fix. Three fixes followed, each in its own commit:

- **D5 on a medium window:** the folder tap stepped back to the list only below 600 dp. From 600
  to 840 dp (a portrait tablet, a split screen) the window still shows one pane, so the list
  changed out of sight. It now steps back wherever the window shows one pane.
- **X2, a shared image's provider:** Android opens `content://0@<authority>` with `<authority>`'s
  provider, so the check now ignores a user prefix. None of the app's providers serves files
  today, so nothing could be read this way; the check is there for the day one does.
- **X2 and X4 before the first login:** the tile, the lock screen and a shared image saved into a
  vault folder that the first clone replaces, and said "Saved to your inbox". They now say to log
  in first.
