# 13.3 — a game's maps, linked and changed from the app

Asked by the owner on 2026-11-27: "I also want to have the possibility to link a map to a game
and/or update the map provider". Interviewed the same morning (M6–M8 below).

## Where things stand (13.2)

- A game page's maps are its `game_maps` frontmatter list. Each entry is an https address or
  `Label | https://…`; only public https addresses are kept (`GameMaps.parse`, the import guard's
  `ImportUrlValidator.isSafe`), anything else stays in the note and out of the app; the first entry
  is the game's main map. `GameMapScreen` opens them (route `game_map?page=&index=`).
- The app can't change the list: the owner types it in the note (13.2.1: "the owner adds
  `game_maps` by hand"). On 2026-11-27, 7 of the 41 game pages had a map, all Fextralife wikis;
  the other 34 carried an empty `game_maps:`.
- What the writes can build on: `FrontmatterLines.setList` and `GamesRepository.editPage` (disk read
  first, `VaultWriteGate`, push requested), the path `played_before` already takes.

## Decisions (owner, 2026-11-27)

- **M6 Where:** all three: the game page, the browser's Share, and the open map.
- **M7 The provider is per game.** Changing it means replacing one game's address with another
  site's page; each game keeps its own provider and nothing is guessed. No preferred site for all
  games.
- **M8 When:** next and on its own, as 13.3, right after 13.2.3; Xbox comes later, after its
  research and interview.

## The batch

- [ ] **ME1 The game page's Maps card.** The page's maps (label · site, the main one first): Add
      (an address, an optional label; the site shown before saving, refused unless public https),
      Change (address or label), Remove, Make main (moves it first). Edits work on the raw
      entries: an entry the app can't read (not https, a private address) is kept as typed and in
      its place; an empty `game_maps:` becomes a list. On a read-only device the card shows the maps
      and `ReadOnlyNotice`, with no controls.
- [ ] **ME2 Share → "Add as a game map".** A shared https link (Chrome shares the page's title and
      its address) offers "Add as a game map" on the share screen: pick the game (the session
      picker's list, searchable), the label prefilled from the shared title, saved like ME1. The
      shared text is untrusted: the address passes the same check, nothing else is read from it. A
      share-launched screen finishes after saving. Not offered on a read-only device.
- [ ] **ME3 "Change map" on the open map.** `GameMapScreen`'s top bar: change this map's address
      or label, "Use this page" (the address the map browser shows now, after moving inside the
      site), and "Add as another map". Hidden on a read-only device.
- [ ] **ME4 Tests.** Pure: the raw-entry edits (add, change, remove, make main, an unreadable entry
      kept, an empty key, the list's indentation as the vault writes it, the page byte-identical
      outside `game_maps`), the shared text's address. Repository on a temp folder: disk read
      first, the read-only gate. Guards: `ReadOnlyScreensGuardTest`, `UiLanguageGuardTest`.
- [ ] **ME5 13.3.0 (130300)** with its CHANGELOG section; the vault's RFC-009 and the cookbook.
