# 13.3 — a game's maps from the app, and the Xbox beside the PlayStation

The release of 2026-11-27. The owner asked, that morning: "I also want to have the possibility to
link a map to a game and/or update the map provider", then "look also to connect my XBox One X on
the App", "PSN/Xbox achievements should lives side-by-side in each Game I owned", and, once 13.2.3
was out: "Xbox connect/achievements should fold into 13.3. Actually, 13.3 will be the release of
the day so any new work will fold into it today". Interviewed the same morning (M6–M8, XB1–XB4).

## Where things stand

- **Maps (13.2):** a game page's maps are its `game_maps` frontmatter list, each entry an https
  address or `Label | https://…`; only public https addresses are kept (`GameMaps.parse`, the
  import guard's `ImportUrlValidator.isSafe`), anything else stays in the note and out of the app;
  the first entry is the main map; `GameMapScreen` opens them (`game_map?page=&index=`). The app
  can't change the list: on 2026-11-27, 7 of the 41 game pages had a map (all from one wiki family),
  34 an empty `game_maps:`. The writes can build on `FrontmatterLines.setList` and
  `GamesRepository.editPage` (disk read first, `VaultWriteGate`, push requested).
- **PSN (13.2.3, the same morning):** signs in; the first sync linked 25 of 32 titles to pages and
  wrote 25 `## 🏆 Trophies` sections. 7 played titles have no page; 16 pages have no PSN title.
- **Xbox, researched on 2026-11-27** (a sweep and an adversarial check of each source):
  - **Sign-in:** an app registered by the owner in Microsoft Entra as a public client (personal
    Microsoft accounts only, "Allow public client flows" on, no secret) signs in at
    `login.microsoftonline.com/consumers` with the device code flow, scope `XboxLive.signin
    offline_access`; then `user.auth.xboxlive.com/user/authenticate` (`RpsTicket` = `d=` + the
    access token, `RelyingParty` `http://auth.xboxlive.com`), then
    `xsts.auth.xboxlive.com/xsts/authorize` (`RelyingParty` `http://xboxlive.com`, `SandboxId`
    `RETAIL`), and every call carries `Authorization: XBL3.0 x=<uhs>;<xsts>`. Apps registered in
    2026 report the whole chain working; no gate applies to `http://xboxlive.com` (the one
    allow-list covers another publisher's game services only). Medium-high confidence: Microsoft documents most of the
    chain for websites, not for apps. No MSAL: the device code flow is the GitHub login's pattern
    on OkHttp.
  - **Tokens:** the Microsoft access token lasts an hour; its refresh token 90 days and replaces
    itself at every use (keep the new one each time); the Xbox user token about 14 days, the XSTS
    token about 16 hours.
  - **Data:** title history from `titlehub.xboxlive.com` (contract 2, decorations
    `achievement,scid`: the title id, name, type, `mediaItemType` — `Application` for One and
    Series games, `Xbox360Game` for back-compat ones —, the achievement summary,
    `titleHistory.lastTimePlayed`); about the 1,000 most recent titles, one page. Play time is the
    cumulative `MinutesPlayed` stat (`POST userstats.xboxlive.com/batch`, a read, whole minutes);
    titles that don't report it are left out (many PC and Game Pass titles; 360 ones contested).
    Achievements from `achievements.xboxlive.com/users/xuid(<xuid>)/achievements?titleId=…`
    (contract 2 for One and Series titles, 1 for 360 ones): name, description, unlocked or not
    with its time, gamerscore, secret.
  - **Not used:** a Microsoft first-party client (it impersonates Microsoft's app, goes against
    Microsoft's API terms, and such clients broke in 2023 and in October 2026); any third-party
    server holding the tokens (OpenXBL, Home Assistant's account linking).
- **The owner's part:** register the app (an Entra directory needs a free Azure account: a phone
  and a card to verify identity, no charge; MFA), then `xboxClientId=<client id>` in
  `local.properties`. Without it the Xbox row stays hidden and nothing else changes.

## Decisions (owner, 2026-11-27)

- **M6 Where, for maps:** all three: the game page, the browser's Share, and the open map.
- **M7 The map provider is per game.** Changing it means replacing one game's address with another
  site's page; nothing is guessed, no preferred site for all games.
- **M8 When:** first "next and on its own"; then, the same morning: 13.3 is the release of the day,
  and Xbox and any new work today fold into it.
- **XB1 Sign-in:** the owner's own Microsoft app, device code.
- **XB2 One section per console:** `## 🏆 Trophies` stays as it is; Xbox gets its own derived
  `## 🎖️ Achievements` beside it (earned only, dated, with the gamerscore). In the app, the two
  cards sit side by side on a wide window and stack on the phone.
- **XB3 Typed hours:** `played_before` shows until a console measures the game; then the measured
  totals of both consoles add up and replace it.
- **XB4 A played game without a page gets one, automatically,** at each sync, with the Other
  template — PSN's 7 included.
- **Defaults taken (the owner may say otherwise):** XB5 the same game on both consoles the same day
  makes one Timeline line with the total; XB6 Xbox syncs with PSN (23:40 and 06:00, the same
  worker, each console on its own and non-fatal).

## The batch

- [x] **ME1 The game page's Maps card.** The page's maps (label · site, the main one first): Add
      (an address, an optional label; the site shown before saving, refused unless public https),
      Change (address or label), Remove, Make main (moves it first). Edits work on the raw
      entries: an entry the app can't read (not https, a private address) is kept as typed and in
      its place; an empty `game_maps:` becomes a list. On a read-only device the card shows the maps
      and `ReadOnlyNotice`, with no controls. Built as `GameMapEdits` (pure, on
      `FrontmatterLines.listItems`/`setListLines`: the raw lines kept, CRLF kept, `date_updated`
      moved), `GamesRepository.addMap`/`changeMap`/`removeMap`/`makeMainMap` (the page read from

      `MapEditDialog`; each edit's result shows in a snackbar above the floating toolbar.

## After the review

Three read-only reviews of the built batch (safety, UI, correctness), their findings fixed before
the release; ui #7 waits for the owner.

- **The maps and the game page:**
  - A label loses the bidi controls a site's title can carry (`GameMaps.cleanLabel`, the label
    taken from the address too), and an address with a user name or password before its host is
    no map (`GameMaps.accepts`; the import's `ImportUrlValidator` is unchanged).
  - The map browser has one *Maps* menu on a device that can write: the other maps, then Change
    this map, Use this page and Add as another map. A read-only device keeps 13.2's Layers menu.
    Use this page and Add as another map of the page shown keep the WebView, with its pan, zoom
    and Back history; a real switch of map builds a new one (a counter keys the view, so a map
    changed back to the first address still loads it).
  - The share screen's *Add as a game map* sits above the load states, so it stays in place; a
    Tech watch article offers none (`ShareImportRepository.start(…, offerAsMap = false)`, kept by
    Try again).
  - No Maps card on a read-only page without maps; the unreadable entries' subtitle ("plus N the
    app can't open, kept in the note"); a map row 48 dp high with "Open the map", its menu
    "Actions for <label>", and "Reveal" on every hidden line (trophies, achievements, checklists).
- **The consoles (Xbox and PlayStation):**
  - A new sign-in counts play from that moment. The sign-in marks its syncs as baselines
    (`xbox_baseline_pending` / `psn_baseline_pending`, device-only, set before the tokens are
    kept when none were) and the sync that saves its snapshot ends it, so a first sync that fails
    or is left hands it to the next run; a baseline writes no session and carries no Xbox minutes
    from before it. Signing in again over an expired sign-in (its tokens kept) starts none, and
    the page says "Signed in again." before the sync's line.
  - Disconnect clears the tokens (and Xbox's session) under the session's lock, and a renewal
    saves the rotated tokens only while the stored refresh token is still the one it renewed;
    otherwise "Xbox isn't connected." / "PlayStation isn't connected." (a log-out clears the
    secrets outside that lock).
  - Xbox minutes: a title's ids in the same call, never split between two; a modern id's counter
    goes to one title only (none when the history lists that id as a title, the smallest id when
    several titles name it). An empty achievements answer keeps a saved file that holds some.
  - `oneLine` (`GameNotes.kt`): console names and titles made one line before they enter a
    section or a created page's frontmatter.
  - The settings pages show *Connected* as soon as the sign-in ends ("Signed in. The first sync is
    reading your … games…"), "Syncing…" in place of the last sync's time while one runs, and
    "Disconnected: Xbox no longer syncs." (PlayStation the same).
  - New tests: `GamesSyncSchedulerTest`, `PsnAccountTest`, and the cases above in the sync,
    account, client and settings tests. 1,359 unit tests after the fixes (1,358 passed, 1 skipped as
    before), lint at 0/0.
- **Left for the owner (ui #7):** the Games tab doesn't scale with the pages XB4 creates (up to 50
  a console and sync, in groups and folds that aren't lazy): a cap with "Show all", or a lazy
  list.
