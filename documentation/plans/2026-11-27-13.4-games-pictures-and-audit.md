# 13.4 — the Games, bulletproof: pictures everywhere, a grid of covers, and the audit's fixes

Asked by the owner on the night of 2026-11-27, once 13.3.0 was out: "I also would like to have the
picture of the game as a preview for the page and everything, the current game does not show the
picture", then "I want this gaming tab/features to be perfect and bulletproof". Three read-only
workflows ran first: the Games tab at scale (review item ui #7), the pictures (what each console
gives, storage, surfaces), and an audit of the whole Games feature (five finders, each checked by
a skeptic: 51 findings confirmed, 3 refuted). The owner's answers, the same night, are below. The
full findings are kept on the Mac in `notes/13.4/` (local, untracked).

## The owner's answers

- **P1 Where:** everywhere a game shows — the game being played, the Playing carousel, every
  library cell and console list, the session picker, the game's page, the open map's header,
  Daily's game lines and the session notification. The Quick Settings tile stays an icon (Android
  tints it).
- **P2 The Games tab:** a grid of covers. The game being played on top as a wide card (its square
  cover cropped wide) with its time and Stop; the Playing carousel filled by covers; Next, Backlog
  and Done as grids of square covers with the title under each (about 3 a row on a phone, 6–7 on
  a wide window); only what is on screen is built and loaded. This closes ui #7.
- **P3 A game's page:** the square cover in the game's expressive shape, its facts beside it
  (hours, trophies, achievements, dates), the state chips below; it replaces today's lone 96 dp
  square.
- **P4 Storage:** console pictures stay addresses in the game data files; each device downloads a
  picture the first time it shows it and keeps it in its image cache. Nothing new in git.
- **P5 No picture:** the game's initials in its own shape and tone; or the owner's own picture,
  set on the game's page or by sharing an image to the app (a shared image then asks: photo note
  or game picture). The owner's picture wins over the consoles', lives in the vault next to the
  page (about 100 KB, named in the frontmatter), and can't be set on the read-only tablet.
- **P6 Tint:** none. Every game keeps its tone from the device's colours; the picture sits on top.
- **P7 Both consoles:** PlayStation's picture first, Xbox's when PlayStation has none (the owner's
  own before both).
- **G1 A long gap between two syncs** (more than about 30 h): the play counts in the game's hours
  but writes no Timeline line, since no console says which day it was.
- **G2 The Games tile on a locked phone** asks for an unlock to start a session, like the
  mission-log tile. Stop and Keep playing stay one tap.
- **G3 One release:** 13.4.0, all of it together.
- Earlier the same night: the 98 Xbox games still without a page are created as XB4 says (50 a
  sync); pings when the vault changes are parked (`2026-11-27-vault-pings.md`).

## Without a choice

- **The Xbox pictures:** titlehub sends most addresses as plain http (`store-images` and
  `images-eds`), and `XboxSync.stateOf` keeps https only, so 22 of 190 titles have a picture. Ask
  for https on those two Microsoft hosts (`images-eds` becomes `images-eds-ssl`); never allow http.
- **A games image loader** the privacy ledger sees: its own OkHttp client with
  `PrivacyLedger.events` under a new persisted purpose (`game_pictures`, "Game pictures"), https
  only, the consoles' image hosts only, no redirects, public addresses, a size cap, about 512 px
  asked where the host takes a size. Today Coil's default client loads them unseen.
