# 12.17 — Games (RFC-009)

**Status:** planned on 2026-11-14 from RFC-009, which lives in the private vault: the owner's
home-session interview (D1–D8), then a code check, a PSN spike and a second interview (D9–D13).
The owner said to build it the same day. The decisions are recorded at the end.

The owner plays on a PS5 and wants the app to know their games the way it knows their days:
a library, a page per game, play time and trophies from the PlayStation Network, sessions in the
day's Timeline, and evenings of play guarded from work. The game list, the pages and their
content live in the vault; nothing here names a game the owner plays.

Unless a path starts with `app/` or `documentation/`, it is relative to
`app/src/main/java/cloud/wafflecommons/pixelbrainreader/`.

## Today (12.16.0)

- **Tabs:** seven in `UserPreferencesRepository.DEFAULT_NAVBAR_ORDER`. A tab added later joins
  the end of a saved order. Below 600 dp the floating bar shows only the first three
  (`ordered.take(3)` in `ExpressiveNavBar`): checked on the Fold emulator, folded = Repo, Habits,
  Chores and Daily. From 840 dp the rail shows them all.
- **Focus sessions (12.14, D9):** `data/focus/` is a fixed-length countdown: one session in
  `UserPreferencesRepository.focusSession`, a promoted ongoing notification (`FocusPlatform`), a
  WorkManager step chain, a Quick Settings tile, a receiver for Stop. A game session is open-ended,
  so it reuses the pattern, not the classes.
- **Timeline markers:** `DailyMarkers` carries only Google ids (`gcal:`, `gtask:`). A Room-held
  line with a new id would need a column, so a Room migration (v32 → v33).
- **Derived content in a note:** 12.11's `## 🩺 Health` is rewritten at each burn from data files
  and skipped by the parser, so nothing of it enters Room.
- **Burning a past day** (`DailyDashboardRepository.burnToDisk(date)`) rebuilds the whole note
  from Room's board for that day. A desktop edit of that day since then would be undone.
- **Modes:** Perso already hides work on Daily (work folders, the mission log, work feeds, Due
  today's work items). The one work item left on a Perso evening is the shutdown banner, due
  until midnight unless the day was closed (`Shutdown.isDue`).
- **Hand-offs:** the composer (`handoff?root=&text=`) writes `<root>/Handoff.md`.
- **Do Not Disturb:** nothing yet. From Android 15, an app targeting 35+ that calls
  `setInterruptionFilter` gets a mode of its own (an implicit `AutomaticZenRule`), not the global
  state; `addAutomaticZenRule` with `TYPE_IMMERSIVE` gives it a name and an entry in Settings ›
  Modes. Both need the user to grant Do Not Disturb access (`ACCESS_NOTIFICATION_POLICY`).
- **Network:** OkHttp, Retrofit, Gson and kotlinx-serialization are already dependencies. Nothing
  new is needed (#9).
- **The vault's frontmatter linter** accepts extra keys; `type` must be in its vocabulary
  (`area` is).

## The design

### G1. Library and pages (D1, D5)

- **A game page** is any vault note whose frontmatter has `game_template`. No folder is
  hard-coded; the owner's pages live in their area for games. Keys: `game_template`
  (`souls-like`, `nightreign`, `roguelite`, `open-world`, `survival-horror`, `lego`; unknown values
  show as "Other"), `game_state` (`backlog`, `next`, `playing`, `paused`, `done`, `100`),
  `started`, `finished`, and the DTO's `title` and `aliases`.
- Found through `file_contents` (the vault scan already mirrors every non-private note), so the
  tab costs no disk read.
- **The Games tab** (route `games`, `Icons.Rounded.SportsEsports`): four groups, Playing, Next,
  Backlog (paused games first, labelled), Done (a 100% badge). A row shows the state, hours, trophy
  % and last played; "Start a session"; the PSN status line. PSN titles no page claims sit in a
  fold with "Link to a page".
- **The game page** (route `game?page=<path>`): state chips (a tap writes `game_state`, one
  frontmatter line, disk read first), hours, trophy %, the trophy list (earned ones dated; the
  others ??? until tapped), the sessions, the note itself (the reader, with marked unticked lines
  masked), the other notes of its folder, and "Ask Claude about this game" (G8).
- **The tab is 8th** (`DEFAULT_NAVBAR_ORDER` + `games`), and **folded, the bar shows four tabs**
  (D9): `take(4)`.

### G2. PlayStation Network (D3, D10)

- **Connect** (Settings → Integrations → PlayStation Network, route `psn_settings`): the owner
  signs in on playstation.com, opens `ca.account.sony.com/api/v1/ssocookie`, and pastes the
  `npsso` value. The app exchanges it at once (authorize → code → tokens) and forgets it. The
  refresh token, the access token and both expiry times go to `SecretManager`
  (EncryptedSharedPreferences). The page shows the status, the last sync, "token expires in N
  days" from Sony's own `refresh_token_expires_in`, Sync now and Disconnect.
- **Sony's app credentials (D10):** the PlayStation App's public client id and secret, used by
  every PSN library, come from `local.properties` (`psnClientId`, `psnClientSecret`) into
  `BuildConfig`, like `githubOauthClientId`. Empty: the PSN row is hidden and Games works by hand.
- **The calls** (read-only, `Accept-Language: en-US`): played games
  (`gamelist/v2/users/me/titles`, PS4 and PS5 categories, paged), trophy titles
  (`trophy/v1/users/me/trophyTitles`), the title-to-set link (`…/users/me/titles/trophyTitles`,
  five ids a call), and for a set whose `lastUpdatedDateTime` moved: its trophies and the owner's
  earned ones. Definitions are fetched again only when the set's version changes. A first sync is
  about 35 requests; a nightly one a handful (the community-measured limit is 300 per 15 minutes).
- **When:** a `GamesSyncWorker` pinned at 23:40, before the 23:50 burn, and at 06:00 for the
  sessions that ran past midnight (`DailyWorkScheduler`, two slots, network required), plus Sync
  now. Each run refreshes the access token first (an hour long).
- **Failure** (a refused refresh token, an API change, no network): the run stops, the vault sync
  is never involved, and the tab and the settings page say "PSN paused: paste a new token" or the
  error. Nothing crashes; Games keeps working by hand.
- **Unofficial API:** Sony can change it or retire the public client at any time; one such report
  is open (§ Spike). The app degrades to manual use, as above.

### G3. What a sync writes (vault-first, #8)

All in `10_Journal/data/games/`, written by the app only, each change based on the file on disk
(an unreadable one is moved aside, never overwritten):

- `psn.json`: the last sync, per title (`titleId`, name, category, play seconds, play count,
  first and last played, trophy set, progress, earned and defined counts), and when.
- `links.json`: PSN title → page. Filled on its own when a PSN name matches a page's title or
  alias (normalised: case, ™ ® ©, punctuation), or by "Link to a page". One page can hold several
  titles (a game and its online mode).
- `sessions/YYYY-MM.json`: the sessions, `psn` or `manual`.
- `trophies/<set>.json`: the set's trophies (number, name, description, grade, hidden, group) and
  the earned dates. Unearned names stay in this data file only.
- `config.json`: the owner's Games settings (`ask_project`, G8); the app only reads it.

And in each linked page (D12): the `## 🏆 Trophies` section, rewritten at each sync like 🩺
Health, with the earned trophies only, dated; and the **trophy markers** (D3): a checklist line
ending with `<!--trophy:<set>#<number>-->` is ticked, with the date, when that trophy is earned.
Nothing else in a page is touched.

### G4. Sessions and the Timeline (D3, D11)

- **From PSN:** at each sync, a title's play time minus the previous sync's is a session. Its
  start comes from PSN's last-played time (the spike says which end of the session that is). The
  first sync only records the baseline.
- **By hand:** G6.
- **One line per game and day:** `- 21:05 🎮 <name> · 2 h 35 <!--game:<page>-->`. Measured time
  wins: a manual start gives the line its time, PSN gives the duration when it measured one.
- **Today:** `burnToDisk(today)` writes the day's game lines among the timeline lines, from the
  sessions files. `DailyMarkdownParser` leaves a marked line out of the board, so nothing of it
  enters Room: no column, no migration, and a cold-start rehydrate can't duplicate it (the
  triple-dup lesson, #7).
- **A past day (D11):** a session found after its day was burned (past midnight, the 06:00 run) goes to
  the day it started. That note's Timeline gets its marked lines replaced, nothing else touched
  (disk read first; up to 7 days back; no note that day → only the sessions file). Never a re-burn.
- **Daily's timeline** shows the day's game lines among the others; a tap opens the game page.
- **History:** Timeline lines of earlier notes that name a game (its title or an alias, whole
  words, the longest match) are read as past sessions without a duration. Nothing is rewritten.
- **No XP** for gaming.

### G5. The burn and the parser (#7)

- `MarkdownBurner.burn` takes the day's game lines and sorts them with the timeline entries.
- `DailyMarkdownParser` skips a timeline line that carries `<!--game:…-->`. A user's own line
  that names a game (no marker) stays theirs.
- Round trip: board + game lines → burn → parse → board (no game line) → burn with the same lines
  → the same file.

### G6. Manual sessions (D3)

- One at a time, kept on the phone (`UserPreferencesRepository.gameSession`, `startMillis|page`).
- **Started** from the Games tab, a game page, or the Quick Settings tile `GameTileService`
  (the last played game; long-press opens the tab). **Stopped** from the notification, the tile or
  the tab.
- **The Live Update:** a promoted ongoing notification (the 12.14 permission), counting up with
  the system chronometer, channel `game_running` (low, quiet), Stop through a non-exported
  receiver. No step chain: nothing moves but the chronometer.
- On stop: a `manual` session in the sessions file, and today's line at the next burn.

### G7. Game nights (D7, D13)

- When a manual session starts in **Perso, outside work hours** (`Visibility.mode`, the schedule),
  the app's own **"Game night"** mode turns on: an `AutomaticZenRule` (`TYPE_IMMERSIVE`) created
  once, activated with `setAutomaticZenRuleState`. Its exceptions are the owner's, set in Settings
  › Modes › Game night. The owner's own Do Not Disturb is untouched, so stopping simply turns the
  mode off.
- **Never in Off** (custody evenings) and never in work hours.
- **Daily:** the shutdown banner stays hidden for the rest of that day (`gameNightDay` on the
  phone). Nothing else is needed: Perso already hides work there.
- **Permission (D7, #9):** `ACCESS_NOTIFICATION_POLICY` in the manifest; the first time a game
  night would start without access, a dialog explains it and opens the system's Do Not Disturb
  access page. The session runs either way.

### G8. Ask Claude (D6)

- "Ask Claude about this game" opens the hand-off composer with `question: <game> — ` typed and
  the project named by `config.json`'s `ask_project`, or none (the owner picks). The vault's
  layout stays out of this repository.

### G9. The read-only device (#18)

The Games tab and the pages are readable. No PSN connection or sync, no state change, no session,
no tile (unavailable), no game night, no Ask Claude; the pages that would write show
`ReadOnlyNotice` and join `ReadOnlyScreensGuardTest`. New writers go through `VaultWriteGate`
(`VaultWriteGuardTest`).

## Spike: the PlayStation Network (2026-11-14)

From the two maintained libraries (psn-api 2.18.1, August 2026; psnawp 3.1.0, October 2026, which
Home Assistant's PlayStation Network integration uses), the community API notes and their issue
trackers:

- **Sign-in:** the `npsso` cookie → `GET ca.account.sony.com/api/authz/v3/oauth/authorize`
  (`access_type=offline`, the app client id, `response_type=code`, scope
  `psn:mobile.v2.core psn:clientapp`; a 302 whose `Location` carries `code=v3…`, or an
  `error_code`, 4165 = expired NPSSO) → `POST …/oauth/token` with the client's Basic header →
  `access_token` (`expires_in` ≈ 1 h), `refresh_token` and `refresh_token_expires_in`, which the
  app reads instead of assuming "about two months". The refresh uses the same endpoint
  (`grant_type=refresh_token`).
- **Play time:** `playDuration` is ISO 8601 to the second (`PT228H56M33S`), with `playCount`,
  `firstPlayedDateTime`, `lastPlayedDateTime`, `category` (`ps4_game`, `ps5_native_game`) and the
  title icon. PS4 titles are listed with their play time; PS3 and Vita are not.
- **Trophies:** sets are `trophy` (PS4) or `trophy2` (PS5); earned trophies carry
  `earnedDateTime`; names come in the requested language.
- **Still answering?** Home Assistant's integration kept shipping in November 2026 with no report
  of a broken sign-in. One open psn-api report (30 September 2026, from two networks in one country)
  has Sony refusing the token step with `4102 Bad client credentials`. It is unconfirmed and
  alone, so the plan keeps PSN, behind the failure handling above.
- **Live check on the owner's account:** see "As checked" below.

## Defaults taken without asking

- Pages are found by their `game_template` key, wherever they are.
- English names from PSN (`Accept-Language: en-US`), as the owner plays.
- No XP for gaming.
- PSN's title icons, no IGDB covers.
- A paused game shows in Backlog with a label.
- "Perso evening" means Perso outside work hours, weekends and days off included.
- Past-day lines: up to 7 days back.
- The sessions and links live in the app's data folder, not in the pages' frontmatter: a page can
  hold several PSN titles.

## As built (12.17.0)

Where the build differs from the text above, or settles what it left open:

- **A board for a day with only a game.** `burnToDisk` writes a day only when Room has its board,
  and a board exists once something was put on it. A session recorded for today now makes sure the
  board exists (`DailyDashboardRepository.ensureDay`); a manual stop also burns the note at once,
  the PSN sync leaves it to the next burn. Found on the emulator: the sandbox had no daily note
  since March, so a session alone never reached a note.
- **No snapshot without its sessions.** `PsnSync` saves `psn.json` only after the sessions are
  saved; their ids come from the previous sync, so a replay replaces them. A title without
  trophies is asked for its set once (`trophyLookedUp`), and every run refreshes the linked pages'
  🏆 sections, so a page linked by hand gets its section without waiting for a new trophy.
- **The hand-off composer reads a typed kind.** "Ask Claude" hands it `question: <game> — `; the
  composer selects the Question chip and keeps only the text, so sending types the prefix once
  (`DeskHandoffFormat.split`).
- **Game night is an `AutomaticZenRule`** (`TYPE_IMMERSIVE`, configuration activity = MainActivity,
  which routes `ACTION_AUTOMATIC_ZEN_RULE` to the tab), and the session's notification is promoted by
  the system (`PROMOTED_ONGOING`).
- **Checked on the Fold emulator** (Android 17, the sandbox vault, 2026-11-14):
  - the rail shows Games 8th; folded, the bar shows Repo, Habits, Chores and Chat;
  - the tab finds the pages by `game_template` and groups them; a page's chips write
    `game_state` (one line), a checklist tick writes one line, a trophy's waiting line reads ???;
  - a session on a Perso Saturday asked for Do Not Disturb access, then (granted) turned the "Game
    night" mode on (`zen_mode` 1, the mode ACTIVE, the owner's own rule untouched); Stop from the
    notification wrote the session to `sessions/2026-11.json`, turned the mode off and removed the
    Live Update; the Game tile started and stopped a session the same way;
  - Daily's timeline showed the day's line; Ask Claude opened the composer with the question typed.
- **The NPSSO check is token-safe, not "64 letters and digits".** The owner's first paste was refused before anything was
  sent (the spike script refused it the same way). The app now takes 32 to 512 token characters, alone or inside the
  page's JSON, lets Sony judge it, and describes a refused paste (length, JSON or not) without showing it.
- **Completed before the release** (the owner's call, 2026-11-15, after reviewing the RFC's v1
  list): the game's page renders the note's own text (`GamePages.prose`: without its title, its
  checklists and the 🏆 section, which have their cards), a ??? item is revealed alone when
  tapped (Reveal still shows all), PSN's icons show through Coil (already a dependency, unused
  until now), and the session picker and the tile start on the game played last, from the
  sessions and PSN's last-played times (`GameSessionController.defaultPage`). The vault's
  `10_Journal/data/games/config.json` names the home project, so Ask Claude preselects it.
  Checked on the emulator.
- **PSN live, on the Fold with the release (2026-11-15):** the NPSSO was accepted and a code came
  back, then Sony's token step refused the client three times: `4102 Bad client credentials`
  (`CLIENT_REJECTED`). This is the report open since 30 September (psn-api #245): Sony no longer
  takes the PlayStation App's public client that every PSN library uses, and no fix is known.
  The failure stayed contained as designed: the page says why, nothing synced, nothing broke.
  The owner's calls: release 12.17.0 as is, and watch psn-api and psnawp for a working client or
  flow, to ship in a 12.17.x (a new client alone is a `local.properties` change and a rebuild).
  Which end of a session `lastPlayedDateTime` marks, the refresh lifetime and the PS4 play times
  stay unconfirmed until then.
- **Correction (2026-11-27, 13.2.3):** the refusal came from the build, not from Sony. The secret
  in `local.properties` had one character too many (17 instead of 16), the same shape as #245's
  curl reproduction (whose report that the library's own header failed too stays unexplained), and
  the public client kept working in November for Home Assistant's integration and other projects.
  See `documentation/plans/2026-11-27-13.2.3-psn-client.md`.
