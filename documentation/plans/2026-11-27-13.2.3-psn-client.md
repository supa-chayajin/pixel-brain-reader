# 13.2.3 — the PlayStation client the build carries

Asked by the owner on 2026-11-27: "Is there any news about the PSN connexion for the App?" There
was no news from Sony: the refusal came from the app's own build.

## What was found (2026-11-27)

- **Nothing moved upstream since the last check (2026-11-16).** psn-api is still 2.18.1 (no commit
  since 2026-08-15) and psnawp 3.1.0 (2026-10-25; the project now lives on Codeberg, GitHub is a
  mirror). Both carry the same public client since December 2022. No new sign-in flow, no word
  from Sony.
- **The public client kept working for others after the Fold's 4102 of 2026-11-15.** Home
  Assistant's PlayStation Network integration is set up on about 11,000 of the installs that share
  analytics (10,958 on 2026-11-26), each signing in afresh with its stored NPSSO at every restart,
  reload or setup retry, and no Home Assistant user reported a 4102, or any other PSN sign-in
  failure, between September and today. One debug log of 2026-11-23, from an install at UTC+1,
  shows seven setup retries, each a fresh NPSSO sign-in, all getting past the sign-in. Dated
  sign-ins in November: the 5th and the 23rd in Home Assistant, and from the 22nd to the 25th in
  three other projects, all with exactly the published client.
- **psn-api #245 (2026-09-30), the one report the 12.17 diagnosis rested on:** its raw-curl
  reproduction sent a 17-character secret where the published one has 16 (one extra character at
  position 16, as on the Fold), and its author found that a wrong secret gives the same 4102. The
  issue also says the library's own, correct header failed the same way, from China; that part
  stays unexplained, and a refusal there can't be ruled out.
- **The app's requests are psnawp 3.1.0's** (endpoints, authorize parameters, token form, headers).
  The one difference that touches client authentication is the Basic value: the libraries
  hard-code it, the app builds it from the two values in `local.properties`, read untrimmed and
  unchecked. The authorize step never uses the secret, so a wrong one still gets a code and fails
  only at the token step, as on the Fold.
- **The owner's check, which printed no value:** `psnClientId` matched; `psnClientSecret` had 17
  characters, one extra at position 16. Corrected the same morning: both now match the published
  values.

## Decisions (owner, 2026-11-27)

1. Ship it as 13.2.3, prepared before the signed build, so one signed APK carries both the
   corrected value and the corrected wording.
2. The gates run niced (`nice -n 10`, two Gradle workers) beside the emulator.

## The batch

- [x] **P1 A 4102 says what it means.** `PsnClient`: "PlayStation refused this build's client id
      or secret (4102)…"; the Games tab: "PSN paused: PlayStation refused this build's client";
      the comments on `CLIENT_REJECTED` and `PsnStatus.needsOwner` no longer say Sony changed.
      After the review: the PSN page offers a new NPSSO only when one would help
      (`PsnStatus.needsNpsso`: an expired sign-in or a refused NPSSO), since a corrected build and
      Sync now fix a refused client; and "then build again", the page's own words.
- [x] **P2 The build warns** when `psnClientId` isn't a lowercase 36-character client id,
      `psnClientSecret` isn't 16 letters and digits, or only one of the two is set; with the
      lengths, never the values. Only the secret's warning names 4102: a wrong id fails earlier, at
      the authorize step.
- [x] **P3 The record corrected** where it said Sony blocked the client: the roadmap's G2, the 12.17
      plan's live check, the 13.1 plan's context.
- [ ] **P4 13.2.3 (130203)** with its CHANGELOG section.
- [ ] **On the Fold, with the signed APK:** a fresh NPSSO signs in, and the first sync answers what

## Later, the owner's call

- **A new NPSSO every ten days?** psnawp's recordings of March and October 2026 show a refresh
  token of 863,999 s (ten days) that a refresh doesn't extend; its 2025 recordings showed 60 days. The app never keeps the NPSSO, so it would need a new paste about every
  ten days; one Home Assistant integration keeps the NPSSO and signs in again before the ten days
  run out. To decide once the Fold shows the real lifetime.
- **Xbox**, asked the same morning: the research is under way. RFC-009's D2 said PS5 only, "Xbox or
  Steam only if you ever add one", so it starts with an interview.
