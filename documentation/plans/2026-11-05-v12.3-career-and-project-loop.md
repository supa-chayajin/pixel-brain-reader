## 2. Ground rules (Settled Decisions)

- **Every number comes from data; nothing is estimated** ("non mesuré" when not recorded). No invented scores or indices.
- **No new heavy screens or wizards** (v12 "Simpler" principle): enrich the existing cards on `EvidenceScreen`, `ObjectivesScreen`, `LoadRecoveryScreen`, `ProjectsScreen`, and wire one-tap entry into the existing `🧭 Coach` chat preset.
- **100% on-device AI** (`LocalAiManager`, `maxOutputTokens = 256`, prompt budget ≤ 2,500–3,000 chars).
- **UI copy in English; AI prompts and generated inbox drafts in French** (`AiLanguage.DIRECTIVE`).
- **Public repo discipline:** no employer, client, product or people names in code, tests, docs or commits.
- **0 lint errors / 0 warnings**, unit tests green, one concern per commit on `main`.

## 3. What is actually missing (the 5 real gaps) & Action Plan

### Step 1 — Link `Objectives` to `Projects` and notes via `LinkDao` (`Objectives.kt`, `ObjectiveRepository.kt`, `ObjectivesScreen.kt`)

**Why:** Right now an `#objectif` note only gathers `material` from `MissionLog` entries sharing its `#tags`. If an `#objectif` note links to a project (`[[20_Projects/MyProject/README]]`) or notes link to the objective (`[[Mon objectif]]`), `ObjectivesScreen` doesn't show them, and project commits don't surface under the objective.

- [x] **1.1** In `ObjectiveRepository.objectives()`, query `LinkDao` (`allNoteLinks()`) and `ProjectRepository.projects(today)`:
  - Resolve **linked projects**: any `20_Projects/<folder>` whose notes are linked from the `#objectif` note or link into it (or share one of `ObjectiveFormat.materialTags(note)`).
  - Resolve **linked notes** outside `20_Projects/` (e.g. RFCs, meeting notes, completed board notes) that link to or from the objective.
- [x] **1.2** Extend `Objective` in `data/work/Objectives.kt` with:
  - `val linkedProjects: List<ProjectSummary> = emptyList()`
  - `val linkedNotes: List<WorkNote> = emptyList()`
  - Update `Objective.stale(today)` so recent commits in a linked project (`project.lastActivity`) also count as progress alongside note edits and tagged log entries.
- [x] **1.3** In `ui/work/ObjectivesScreen.kt` (`ObjectiveCard` when expanded):
  - Show a **Linked projects** section (project title, 14-day commit count, and a tap to open the project or its `README.md`) and **Linked notes** (filtered by `Visibility.isVisible`).
- [x] **Tests:** `ObjectivesTest` — an objective linked to a project with a recent worklog is not `stale`; linked projects and notes resolve both ways (`source → targetKey` and backlinks).

### Step 2 — Bring `Projects` (commits/worklogs), `Objectives` (milestones), `Meetings` and `byRequester` into `EvidenceReport` (`EvidenceReport.kt`, `EvidenceRepository.kt`, `EvidenceScreen.kt`)

**Why:** `EvidenceRepository.figures(period)` currently ignores `20_Projects/` worklogs, `#objectif` milestones, `MeetingRepository` meeting totals, and `[demandeur:: …]` breakdown — and hard-locks `completed` to `workFolders` only, so you cannot generate a report for your personal/public projects.

- [x] **2.1** Add a scope toggle on `EvidenceScreen` / `EvidenceViewModel`:
  - **Work** (default: mission log + `workFolders` notes & work projects) vs. **Personal** (notes & `20_Projects/` outside `workFolders`), respecting `Visibility.hideWork`.
- [x] **2.2** Extend `EvidenceFigures` (`data/work/EvidenceReport.kt`) with pure, measured figures from the period (`period.start..period.end`):
  - `val byRequester: Map<String, List<LogEntry>>`: grouped by `entry.requester` (`[demandeur:: …]`), with open request counts and off-ticket minutes per requester role.
  - `val meetings: Int` and `val meetingMinutes: Int?`: from `MeetingRepository` for the period ("non mesuré" when no `duration_min` was recorded).
  - `val projectActivity: List<ProjectPeriodActivity>`: per visible `20_Projects/<folder>` active in the period, the sum of `WorklogDay.commits`, `sessions`, and the key notes moved to `DONE` in that project during the period.
  - `val objectivesProgress: List<ObjectivePeriodProgress>`: objectives that had log material in the period or were updated in the period, with their `done / total` milestone count.
- [x] **2.3** Render the new sections in `EvidenceReport.render()`:
  - In `## En chiffres`: add `| Réunions | X (Y h Z / non mesuré) |` and `| Commits (projets) | X sur Y projet(s) |` (when > 0).
  - Add `## Par demandeur` (requester role: entries, open requests, off-ticket hours) right after `## Par rôle`.
  - Add `## Objectifs` and `## Projets actifs` (with commit counts from the worklogs and links to `[[README]]` / `_portfolio` notes).
- [x] **2.4** Improve `EvidenceReport.facts(figures)` for the optional Gemini Nano `## Synthèse`:
  - Prefix each fact with its `[role]` when present (`"[Lead] décision : …"`), include project commit totals and objective progress, and ask Nano to structure its ≤ 5 sentences around the roles held and the concrete outcomes (within the 2,500-char input budget and 256-token output limit).
- [x] **Tests:** `EvidenceReportTest` — verify `byRequester`, meeting totals, project commit aggregation over a `ReportPeriod`, and role-prefixed `facts()`.

### Step 3 — Show *where* the load comes from in `LoadRecovery` (`LoadRecovery.kt`, `LoadRecoveryRepository.kt`, `LoadRecoveryScreen.kt`)

**Why:** `LoadRecovery` tells you *that* your week is +35% heavier than usual and recovery dropped, and shows heavy vs. light day correlations, but doesn't show *which* roles, requesters (`[demandeur:: …]`), tags, or open `@moi` actions are driving the off-ticket and request load.

- [x] **3.1** Add pure breakdown data to `LoadRecoveryReport` (`data/work/LoadRecovery.kt`), computed over the last 7 days and the 8-week window (zero estimation):
  - `val weekByRole: List<RoleLoad>`: each `role` present in the last 7 days' log, with its `offTicketMinutes`, `requests`, and `refusals`.
  - `val weekByRequester: List<RequesterLoad>`: each `requester` (`[demandeur:: …]`) in the last 7 days, with `requests` (and how many are still open) and `offTicketMinutes`.
  - `val openRequests: List<LogEntry>`: open requests (`LeaveDocuments.isOpenRequest`) from the log.
  - `val overdueMyActions: Int`: count of open `@moi` actions across the vault whose `due < today` (from `MeetingRepository`).
- [x] **3.2** Render a **"Where this week's load comes from"** `SectionCard` on `LoadRecoveryScreen` (and summary bullets inside `OverloadCard` when `OverloadSignal` is active):
  - Lists the week's off-ticket time and requests broken down by `role` and by `requester` (`demandeur`), plus the count of open requests and overdue `@moi` actions, with a one-tap link to open `MissionLogScreen` or `MeetingsScreen`.
- [x] **Tests:** `LoadRecoveryTest` — verify `weekByRole`, `weekByRequester`, and `openRequests` aggregation on sample log entries.

### Step 4 — One-tap "Ask Coach" from `Objectives`, `LoadRecovery` & `Evidence` (`ChatViewModel.kt`, `ObjectivesScreen.kt`, `LoadRecoveryScreen.kt`, `EvidenceScreen.kt`)

**Why:** The `🧭 Coach` preset (`id = "coach"`) already exists in `PromptPresetFormat.DEFAULTS`, and `ObjectiveSlotWorker` already brings the user to `ObjectivesScreen` on Friday. What's missing is a bridge that sends structured context (an objective's milestones + log material, or this week's load breakdown) into a `🧭 Coach` chat turn so the user doesn't have to copy-paste or re-explain their week.

- [x] **4.1** Add a `seedCoachPrompt(contextBlock: String)` entry point on `ChatViewModel` (and navigation route parameter / shared state in `MainViewModel`):
  - Switches `ChatMode` to `ChatMode.PRESET` with the `coach` preset (`PromptPresetRepository.presets` matching `id == "coach"`).
  - Sends a concise French user message built from the screen's facts (capped at 1,200 chars, stripped through `ConfidentialityGuard` if needed), so `🧭 Coach` immediately replies with its 1-sentence rephrase + 1 open question:
    - **From an `ObjectiveCard` ("Coach"):** the objective's title, open/due milestones, linked project activity, and last 5 log entries (`material`).
    - **From `OverloadCard` / `LoadRecoveryScreen` ("Triage with Coach"):** the week's meeting + off-ticket minutes vs. usual, the top `demandeur` / `role` drains, and the open requests — asking what to refuse, renegotiate or turn into a ticket.
    - **From `EvidenceScreen` ("Coach on this period"):** the period's figures by role, top decisions, and completed notes — asking which outcome is missing from the log before writing the review draft.
- [x] **Tests:** Unit test for the French seed message builders (stays under the character budget, includes only measured fields, contains no French UI copy in the Compose callers).
